## 一、产品概述与愿景

### 1.1 产品定位

**AI 自动化写作平台** 是一款面向内容团队的企业级写作协作产品，以「热点输入 → 大纲生成 → 正文创作 → 审核/配图 → 发布」为主线，结合 RAG 知识库与信源管理，实现 AI 辅助下的高效、可追溯的内容生产流程。

### 1.2 核心价值

- **效率**：从选题到成稿的流程化、半自动化，减少重复劳动。
- **质量**：基于 RAG 的引用与自动审核（敏感词、事实性检查），降低合规与事实错误风险。
- **协作**：以「行动中心」为入口，统一待办、队列与 AI 洞察，便于团队协同。

### 1.3 目标用户

- 内容运营 / 编辑：日常选题、写稿、审核、发布。
- 团队负责人：查看整体进度、队列与质量概况。
- （规划中）管理员：信源配置、知识库管理、审核规则配置。

## 二、用户场景与故事

| 场景 | 用户目标 | 关键功能 |
|------|----------|----------|
| 快速开写 | 从热点或建议直接进入创作并预填选题 | 概览行动卡片 → 跳转创作工作台并注入 prompt |
| 大纲驱动写作 | 先定大纲再生成正文，可编辑大纲 | 选题输入 → 一键生成大纲 → 块编辑 → 确认后生成正文 |
| 有据可依 | 写作时参考 RAG 检索结果并引用 | 左侧 RAG 卡片、选中引用、流式输出中标注「引用中」 |
| 质量把关 | 发布前发现敏感词与事实性问题 | 右侧自动审核报告（敏感词 / 事实性错误） |
| 信源与知识管理 | 维护采集源与知识库，供 RAG 使用 | 信源管理页（状态/筛选/表格）、知识库页 |

```
┌─────────────────────────────────────────────────────────────────┐
```

- **概览**：行动中心、可操作指标卡、创作队列、AI 洞察卡片。
- **创作工作台**：四阶段工作流（选题 → 大纲 → 正文 → 配图/审核），RAG 区、流式输出、灵感球、自动审核报告。
- **信源管理**：状态卡、搜索筛选、信源列表（表格）。
- **知识库**：知识库管理（当前为占位/规划）。
- **发布**：发布管理（当前为占位/规划）。

## 四、功能详细说明

### 4.1 概览（Dashboard）

**路由**：`/`  
**视图**：`src/views/Dashboard.vue`

#### 4.1.1 需求要点

- **主行动锚点**：Hero 区提供引导文案与可点击行动卡片，引导用户进入创作或查看队列。
- **可操作指标**：每个统计卡具备底部状态说明与明确操作（如「去创作」「查看队列」）。
- **优先级布局**：创作队列在视觉与布局上处于中心位置，便于快速处理待办。
- **AI 洞察**：固定/悬浮的 AI 人设卡片，浅色主题（白底、slate 文案），提供简短建议或提示。

#### 4.1.2 关键组件

- `DashboardHero.vue`：Hero + 主行动 + AI 洞察卡片。
- `ActionableStat.vue`：带状态与操作的指标卡。
- `CreationQueue.vue`：创作队列列表与入口。

#### 4.1.3 交互与数据

- 点击「建议选题」「去创作」等入口时，通过 `useEditorStore` 写入初始 prompt 并跳转 `/editor`。
- 数据当前为前端模拟，后续需对接待办/队列/统计接口。

---

### 4.2 创作工作台（Editor）

**路由**：`/editor`  
**视图**：`src/views/Editor.vue`

#### 4.2.1 工作流阶段（Stepper）

| 阶段 | 名称 | 主要能力 |
|------|------|----------|
| 1 | 热点/选题输入 | 空状态引导、手动输入、热门标签一键填充；模拟 RAG 拉取 |
| 2 | 大纲生成 | 流式展示大纲、大纲块编辑、AI 润色、确认大纲后进入正文 |
| 3 | 正文创作 | 按大纲流式生成正文，左侧大纲高亮当前段落 |
| 4 | 配图/审核 | 占位引导至右侧栏；右侧展示自动配图与自动审核报告 |

#### 4.2.2 编辑器与布局

- **编辑区**：`contenteditable` 居中、最大宽度约 720px，无边框、纸感阅读体验。
- **左侧 RAG 区**：
  - 卡片 hover 轻微右移（`hover:translate-x-1`），选中态 `border-blue-600`。
  - 流式生成中可标记「引用中」的 RAG 项。
- **右侧栏**：
  - 自动配图（占位/示例）。
  - **自动审核报告**：敏感词检测（红色）、事实性错误（琥珀色），含数量与具体标签/描述。
- **灵感球**：跟随光标或选区附近的浮动入口，支持「生成大纲」「生成灵感」等操作（可扩展为更多选项）。

#### 4.2.3 流式输出与状态

- **StreamingOutput.vue**：模拟 AI 逐字输出，末尾蓝色呼吸光标；可发出 `segment` 等事件供引用高亮。
- **状态管理**：工作流阶段、当前选题、大纲、正文、审核结果等建议沉淀至 Pinia（如 `useEditorStore`），便于与后端对接。

#### 4.2.4 响应式

- 主布局下，左侧创作侧边栏在 &lt;1440px 时自动收起到约 80px，保证主编辑区可用性。

### 4.3 信源管理（Sources）

**路由**：`/sources`  
**视图**：`src/views/SourceManagement.vue`

#### 4.3.1 需求要点

- **状态概览**：活跃信源数、今日采集量、告警数等卡片。
- **搜索与筛选**：按平台、采集频率、状态等筛选。
- **列表展示**：通用表格组件（如 `AppDataTable.vue`），支持插槽扩展列与操作。

#### 4.3.2 数据与对接

## 五、设计约束与规范

以下约束对所有页面与组件生效，详见 `.cursor/rules/designrules.mdc` 与 `.cursor/rules/component-standard.mdc`。

### 5.1 视觉与主题

- **主色**：Blue-600（#1677FF），悬停 Blue-500；仅允许 Slate 灰阶与规范内功能色（Success/Warning/Danger）。
- **布局**：主内容区最大宽度 1600px；1920px 下左右边距约 160px，1280px 下约 40px。
- **圆角**：不超过 12px，优先 `rounded-md` / `rounded-lg`。
- **字体**：Inter + PingFang SC，正文行高 1.6。

### 5.2 组件与实现

- **框架**：Vue 3，SFC + Composition API，禁止 React/JSX。
- **图标**：统一使用 `lucide-vue-next`，笔画粗细一致（如 2px）。
- **样式**：优先 Tailwind，8px 步进间距；禁止硬编码色值，须映射 Tailwind 或 CSS 变量。

### 5.3 交互约定

- AI 生成中：流式区域使用呼吸光标或 `animate-pulse` 等轻量动效。
- 审核风险项：使用 `border-l-4 border-amber-500` 等左侧条标注。
- 加载态：RAG 检索等使用骨架屏（Skeleton）占位。

## 六、技术栈与架构（当前）

- **前端**：Vue 3、Vite、TypeScript、Tailwind CSS、Vue Router、Pinia。
- **图标**：lucide-vue-next。

## 七、非功能需求

### 7.1 性能与体验

- 首屏与路由切换保持流畅，大列表考虑分页或虚拟滚动。
- 流式输出阶段保持界面可响应，避免长时间阻塞。

### 7.2 兼容与适配

- 支持现代浏览器（Chrome、Edge、Safari、Firefox 近期版本）。
- 主布局在 1280px～1920px 下可读可用；&lt;1440px 侧边栏收缩。

### 7.3 可维护性

- 新组件需符合 `component-standard.mdc`（SFC 结构、命名、注释）。
- 页面与路由对应关系清晰，业务状态集中在 Store，便于后续接入真实 API。

## 八、版本与后续规划

### 8.1 当前版本（前端原型 v1）

- 概览行动中心、创作工作台四阶段工作流、RAG 与审核报告 UI、信源管理列表、侧栏与路由。

- **Step 4**：配图/审核在中间列的可交互面板（而不仅依赖右侧栏）。
- **知识库与发布**：从占位演进为完整功能模块，并补充相应 PRD 小节。
